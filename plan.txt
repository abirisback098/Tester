PROFESSIONAL ROUTINE PLANNER — MASTER PLAN
Version: 2.0
Status: Working specification

PURPOSE
Build a professional, editable routine planner that can grow from a daily routine into a full weekly planning system and later be deployed as a hosted web app and APK-ready Android app.

1. CORE SCHEDULING MODEL

The schedule is made from time blocks.

Each block has:
- Start time
- Duration
- End time (calculated)
- Activity / task name
- Optional notes
- Optional notification

TIME-UPDATE RULE
- The user can enter or change a block's start time.
- The user can enter duration in hours and/or minutes.
- When a block changes, only the immediately following block's start time is recalculated from that change.
- Later blocks are NOT automatically shifted.
- Example:
  Block 1: 6:13 → 7:30
  Block 2: 1 hour → automatically becomes 7:30 → 8:30
  Block 3 remains unchanged until the user edits it.
- This same rule applies when the duration changes by any number of minutes.
- Every block remains independently editable.

2. DAILY ROUTINE

Daily routine starts with empty editable blocks so the user can set the activities later.

Initial structure:
- Block 1: 6:00 → [editable]
- Block 2: [calculated from Block 1] → [editable]
- Block 3: [independent] → [editable]
- Additional blocks can be added at any time.

No fixed activities should be forced into the initial routine.

3. WEEKLY PLANNING

Add a weekly layer with:
- Monday
- Tuesday
- Wednesday
- Thursday
- Friday
- Saturday
- Sunday

Each day has its own independent schedule.

Weekly features:
- Create a daily routine for each day.
- Copy a routine/template to another day.
- Modify one day without changing the others.
- Add or remove rows/blocks freely.
- Keep the same local time-update rule for every day.
- Support different routines on different days.

4. EDITING EXPERIENCE

The interface should make editable values obvious without being visually noisy.

Required editing features:
- Clear visual indicator for editable times.
- Easy inline editing.
- Add row/block action.
- Delete row/block action.
- Edit activity and notes.
- Keyboard-friendly editing.
- Save changes reliably.
- Avoid accidental cascading changes.

5. DATA PERSISTENCE & DEPLOYMENT

Deployment target:
- Hosted application on Render.

Persistence requirements:
- Routine data must survive refreshes and app restarts.
- Hosted storage should be persistent rather than relying only on browser memory.
- The design should support access from multiple devices later if needed.

6. NOTIFICATIONS

The planner should support scheduled reminders for routine blocks.

Notification behavior:
- User can enable a notification for a specific block.
- User can choose when to notify, such as at the block start or a chosen number of minutes before.
- Notifications should use the block's current scheduled time.
- If a block's time changes, its related notification schedule should be updated accordingly.
- Notifications should continue to work for the Android APK when notification permission is granted.
- The app should work toward reliable offline reminder delivery on Android for scheduled notifications.

Permission requirements:
- Request Android notification permission when needed.
- Explain why notifications are requested.
- Gracefully handle permission being denied.

7. APK / ANDROID TARGET

The application should be designed so it can later be packaged and distributed as an APK.

Android priorities:
- Touch-friendly controls.
- Responsive layout.
- Reliable local notification scheduling.
- Persistent account/routine data through the hosted backend.
- Clear notification permission flow.

8. VISUAL / UI-UX DIRECTION

Overall goal:
- Professional
- Calm
- Clean
- Functional
- Long-term usable

Preferred visual direction:
- Neutral/light base background.
- Neutral cards and surfaces.
- One restrained accent color, preferably a muted blue.
- Use spacing, hierarchy, alignment, and typography instead of decorative effects.
- Subtle visual indication for editable fields.
- Strong readability and clear states.

Avoid these design patterns:
1. Purple-to-blue gradients
2. Gradient hero text
3. Emojis in headings
4. Inter font everywhere
5. Colored border cards
6. Glassmorphism cards
7. Low-contrast dark mode
8. Three icon boxes in a row
9. Badge above the headline
10. Lucide icons everywhere
11. Untouched shadcn UI
12. Fade-in on scroll
13. Cursor-following beam
14. Buttons that only fade on hover
15. Inconsistent spacing
16. Em dashes everywhere
17. Generic buzzword copy
18. Serif italic accents
19. Space Grotesk + Instrument Serif combination

Also avoid unnecessary decorative animation, excessive cards, visual clutter, and over-designed dashboards.

9. MOTION / ANIMATION

Use only subtle functional motion.

Allowed examples:
- Smooth add/remove row transitions.
- Brief highlight when a block is updated.
- Small state transitions that help the user understand what changed.

Do NOT use fancy or attention-seeking animation.

10. PLANNER UX PRINCIPLES

- The schedule should feel like a tool, not a marketing page.
- The user should always understand what can be edited.
- Changing one block should have predictable effects.
- Later blocks must not unexpectedly move.
- Important actions should be easy to find.
- The interface should remain usable on both desktop and phone screens.
